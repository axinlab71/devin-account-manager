# 真实客户端验收手册 — 额度轮换 + URI 热切换

> 目的：把 `feat/safe-account-rotation` 分支从"已实现"验收为"真实可用"。
> 环境要求：隔离的 Windows 测试环境（VM 或专用账户），**两个本人控制的
> Devin 账号 A、B**，已安装官方 Devin Desktop。
> 全程不得把 Token/授权码/会话内容写进日志或发给任何人。

## 0. 前置：建立官方登录基线（必须先做）

在**不安装本工具**的机器上：

1. 官方 Devin Desktop 正常登录账号 A，发一条 AI 消息确认可用。
2. 记录基线快照（只读）：
   - `%APPDATA%\Devin\User\globalStorage\state.vscdb` 的键清单（可用
     `sqlite3 state.vscdb "SELECT key FROM ItemTable"` 导出到文本比对）
   - `Local State` 文件哈希
   - 注册表 `HKCU\Software\Classes\devin` 协议注册项
   - Windows 凭据管理器中的相关条目名（不导出内容）
3. 官方退出登录 → 网页重新登录，确认全流程可用 → 作为对照基线。

## 1. 安装/启动无害性

- 安装并启动管理器，不做任何操作 → 打开 Devin：仍显示账号 A、能对话。✅/❌
- 关闭管理器再开 Devin：无变化。✅/❌

## 2. 只读操作不改变登录态

- 导入 A、B 两个账号；对两者分别点刷新额度 → Devin 中账号仍是 A。✅/❌
- 设置 → 额度轮换：模式设"仅提醒"，开监控 → 等一轮扫描 → Devin 登录态不变。✅/❌
- 执行 `probe_auth_compatibility`（只读探测）→ Devin 登录态不变。✅/❌

## 3. 推荐链路（不动客户端）

- 设置 → 额度轮换 → "推荐并等待确认"，把阈值临时调高（如 30%）或用
  低额度账号触发推荐。
- 观察：横幅出现、目标账号合理、跨组织有醒目提示。
- 点"暂时忽略"→ 同一低额度周期内不再弹（等新一轮额度周期才再弹）。✅/❌
- 点"切换到此账号"→ **客户端运行时**应触发官方 URI 登录。

## 4. L2 URI 热切换验收（核心）

前提：Devin Desktop 正在运行、窗口保持打开。

1. 点击"切换到此账号"→ 预期：Devin 弹出官方"是否切换账号"确认框。✅/❌
   - 若无弹窗：URI 未被路由（检查 devin:// 协议注册、客户端版本），
     记录现象，标记 L2 不可用，保持 `blocked`。
2. 在官方弹窗点确认 → 不重启窗口，观察左下角/账号区是否变为 B。✅/❌
3. 管理器点"验证生效"→ 应显示"已切换到 B"（label 匹配）。✅/❌
4. **发一条 AI 消息**确认返回正常且新账号计费（官方 UI 可查额度变化）。✅/❌
5. 反向 B→A 重复一次。✅/❌
6. 在官方弹窗点"取消"→ 管理器"验证生效"应显示仍是旧账号；
   再次点"切换"应可重试（`awaiting_client` 是可重试态）。✅/❌

**判据**：4 步全过 → `native_hot_switch` 可从 `implemented_unverified`
升 `supported`；任何一步失败 → 记录现象、保持 blocked，不降级为假成功。

## 5. 官方回归（最关键，不得跳过）

- 手动切号 A→B→A（原有重启式切号）后：在 Devin 里**官方退出登录** →
  官方网页登录 → 授权完成 → 能对话。✅/❌
- URI 热切换后同样做一次官方退出→重登。✅/❌
- 关闭/卸载管理器 → Devin 独立登录一切正常。✅/❌
- Devin 客户端升级一次后重复基线检查。✅/❌

## 6. 存储 diff（区分官方自改 vs 本工具改动）

对 §0 的快照做前后对比，逐项核对差异是否都在已批准写入范围内：

- `windsurfAuthStatus`：我们的字段更新 + 官方未知字段保留
- `windsurf_auth.sessions`：数组合并（新会话置顶，旧会话仍在）
- `codeium.windsurf`：仅 `apiServerUrl`/`pendingApiKeyMigration` 变化，
  `installationId` 原值不变
- `windsurf_auth-*`：除当前 label 两个键外全部原样
- `Local State`、协议注册、凭据条目名：应无差异

## 7. 异常路径

- 客户端未运行时点"切换到此账号"→ 应返回"客户端未运行"blocked，
  不应静默启动或写库。✅/❌
- 轮换中途强杀管理器进程 → 重开后状态一致（建议仍是可重试态，官方
  登录不受影响）。✅/❌
- 断网时点确认 → 铸 ott 失败 → 报 `failed` 可重试，不写任何客户端状态。✅/❌

## 8. 通过标准

- §5 全过（官方登录机制完整）
- §4 至少 URI 拉起 + 官方弹窗 + 会话切换 + AI 请求为新账号
- §6 diff 无计划外写入
- 全过之后才能更新 `get_switch_capabilities` 与文档中的"未实测"标注。

任何一项失败：记录实际现象、截图（脱敏）、相关日志（不含凭据），
**不要**把失败标记为通过，也不要为绕过失败而放宽门禁。
